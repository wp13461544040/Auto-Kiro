# Kiro 优化功能快速参考

## 新增功能

### 1. 代理池状态检查
```
启动任务前自动检查可用代理数
- 无可用代理 → 阻止启动，提示错误
- 代理不足 → 显示建议并发数
```

### 2. 动态并发控制
```
并发数建议 = 可用代理数 / 2
最大并发数 = 20

例如:
- 10个代理 → 建议并发5
- 30个代理 → 建议并发15
- 50个代理 → 建议并发20 (上限)
```

### 3. 冷却管理增强
```go
// 前端新增按钮
- "重置全部冷却": 一键解除所有代理冷却
- "解除冷却": 单个代理解除冷却
```

### 4. 时序真实性
```
点击次数: 正态分布 (平均5次, 标准差3)
按键间隔: 对数正态分布 (平均200ms, 偶尔长停顿)
页面停留: 正态分布 (4-10秒, 平均7秒)
点击位置: 聚集在常见区域
```

### 5. 验证码优化
```
Outlook:
- 超时时间: 180秒 (3分钟)
- 轮询间隔: 8秒

临时邮箱:
- 超时时间: 120秒 (2分钟)
- 轮询间隔: 5秒
```

## 配置建议

### 代理池大小
```
并发1  → 最少3个代理
并发5  → 最少12个代理
并发10 → 最少25个代理
并发20 → 最少45个代理
```

### 并发策略
```
保守: concurrency = availableProxies / 3
平衡: concurrency = availableProxies / 2 (推荐)
激进: concurrency = availableProxies
```

### Debug 模式

```go
- 指纹生成细节
- 加密服务测试结果
```

## 故障排查

### 问题: "代理池无可用代理"
```
原因: 所有代理都在冷却中或已禁用
解决:
1. 点击"重置全部冷却"
2. 添加更多代理
3. 等待冷却时间过去 (8小时)
```

### 问题: "并发数过高"
```
日志: "建议并发数: X (当前设置: Y)"
解决:
1. 查看可用代理数
2. 手动调整并发数为建议值
3. 或增加代理数量
```

### 问题: "验证码超时"
```
Outlook: 180秒超时
临时邮箱: 120秒超时

可能原因:
- 邮件服务延迟
- 验证码邮件被拦截
- 邮箱服务异常

解决:
1. 检查邮箱服务状态
2. 重试任务
3. 更换邮箱服务商
```

### 问题: "WorkflowID 提取失败"
```
启用 Debug 模式查看完整响应:
cfg.Debug = true

检查:
1. 响应结构是否变化
2. redirect.url 是否包含 workflowID
3. 是否有顶层 workflowID 字段
```

## 性能优化

### 内存使用
```
单个任务: ~50MB
并发10: ~500MB
并发20: ~1GB

建议: 8GB+ 内存
```

### 网络带宽
```
单个任务: ~2-5MB 流量
并发10: ~20-50MB 流量

建议: 10Mbps+ 带宽
```

### CPU 使用
```
单个任务: ~5-10% (4核)
并发10: ~30-50% (4核)

建议: 4核+ CPU
```

## 监控指标

### 关键指标
```
成功率 = 成功数 / 总数
代理利用率 = 使用中代理 / 总代理数
平均耗时 = 总耗时 / 完成数
```

### 健康阈值
```
成功率 > 70%: 健康
成功率 50-70%: 警告
成功率 < 50%: 异常

建议:
- 成功率低 → 检查代理质量
- 耗时长 → 降低并发数
- 频繁超时 → 检查网络连接
```
